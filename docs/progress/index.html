        How these estimates are calculated

        Expected pull requests for a stream is the planned count, or the actual open-plus-merged count if more land. Progress is (merged + half of the open pull requests) divided by that expected count. A stream with no open or merged pull request stays at 5% while it is still coding. It stops at 95% until nothing is open and at least the planned number are merged, and then it reads 100%. Closed pull requests that were not merged stay in the list and do not move the percentage. The page refreshes every 2 minutes. GitHub allows 60 unauthenticated requests an hour, so a full hour of refreshes would spend the budget; the page saves a snapshot in this browser and waits out the limit.
